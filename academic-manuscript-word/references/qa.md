# 格式 QA 与逐页视觉闭环

## 自动检查

逐项记录 pass/fail/needs_review/not_applicable，并提供位置、有效值、期望配置键、修复和剩余问题；无法检测不能写 pass。

| 检查 | 要求 |
| --- | --- |
| 内容保全 | 修改前后快照一致，允许差异逐项列出；包括图表、公式和所有 story |
| 字体一致性 | 检查继承、主题、直接格式与实际字体可用性；记录数学/符号例外 |
| 字号一致性 | 各角色有效字号对照配置；不要要求标题与正文同字号 |
| 标题层级 | Title 与四级样式、大纲级别正确；跳级提示人工核对，禁止生成缺失标题 |
| 段落间距 | 按角色检查段前段后；识别作为布局填充的空段但保护结构段 |
| 行距与缩进 | 倍数/磅数语义正确，字符首行与悬挂缩进不冲突，无模拟缩进 |
| 分页控制 | widowControl、keepNext、keepLines、break 与全部节属性有效 |
| 图表几何 | 图片 extent/锚点、表格/单元格网格和缩进不越当前节/栏边界 |
| 表格 | 三线表、宽度、重复表头、拆行规则、无固定高度裁切 |
| 题注与引用 | 独立样式、SEQ 实际结果、书签与 REF 正确，无断链/重复编号 |
| 页眉页脚 | 页码域、首页/奇偶页、节之间延续和边距正确 |
| 参考文献 | 有效字号、悬挂缩进、间距符合选定配置；体例未转换不得声称完全合规 |

OOXML 开关只是结构检查，不能证明实际没有孤行、跨页题注或溢出。页数与行布局必须经渲染验证。

## 强制渲染与视觉检查

1. 查明可用 DOCX→PDF 引擎及字体。优先使用能正确处理现有对象和域的 Microsoft Word；LibreOffice 可作为替代，但记录引擎/版本、替代字体与域兼容性。可使用现有 documents 技能的 render_docx.py，在实际运行环境确认参数和依赖，不硬编码机器路径。
2. 更新可安全更新的域，另存同版本 DOCX，导出 PDF，再把 PDF 全部页面渲染成图像。记录 DOCX/PDF 哈希、页数、引擎、配置路径和迭代编号。
3. 真正打开每页图像；总览可辅助定位但不能代替逐页正常阅读尺度的检查。密集表格、公式、题注和疑似越界处放大复查。
4. 检查字体缺字、题目与标题层次、行距段距、意外空白页、过大空白、标题悬空、正文孤行、公式裁切、图片越界、表格溢出、题注错页、跨页表头、页眉页脚与页码。对跨页对象同时查看相邻页面。
5. 明显格式问题自动修复：纠正覆盖样式的布局属性、图表尺寸与网格、题注保持规则、误用分页和配置不一致。只使用配置允许的修复；不得通过删文字、缩写表头、改公式、裁图或任意缩小正文来塞入页面。
6. 修改后重复完整导出，并重新检查最终版本的每一页；不能拿旧 PDF 作为新 DOCX 的验收证据。连续迭代上限来自 qa.max_auto_repair_iterations；超过上限仍有问题则保留成果、列出阻碍并标为待验收，而不是忽略。

无渲染引擎、缺字体、不可兼容对象或无法逐页查看时，报告结构检查结果和具体未验收项；不得宣称“视觉 QA 通过”。

## QA 记录

qa-report.json 应包括 source/output、resolved_config、content_diff、engine、font_availability、checks、iterations、pages_reviewed、page_count、unresolved、final_docx_hash、final_pdf_hash。pages_reviewed 记录每页发现/修复/最终状态。只有内容保全通过、自动检查无未解释失败、最终全部页面人工式视觉审查完成且无未解决明显版式问题时，overall_status 才可为 passed。
